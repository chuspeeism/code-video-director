# 自检与评分（第 6 步静帧、第 8 步成片）

**做完不看，等于没做完。** 模型能看图：出拼图，像挑剔的导演一样看。

## 1. 静帧自查（全片渲染前）

1. 挑 4–8 个关键时刻：开头 0.5 秒、每段的代表画面、高潮那一帧、落版。
2. `node <skill>/scripts/render.mjs index.html --out out --stills 0.5,3,8,15,22,28`，看 `out/stills/sheet.jpg`。
3. 逐张对照导演单：风格元素清单是不是每张都有？字读得清吗？主体清楚吗？
4. 按 SKILL.md 的评分表打分，<8 分的先修。在静帧上修一个问题只要几分钟，全片渲完再发现要多花十几分钟。

## 2. 成片自检

```
python3 <skill>/scripts/qa.py 成片.mp4 --expect-size 1920x1080 --expect-dur 60 --music --no-voice --out qa
```

- 看 `qa/qa_report.json` 和打印的摘要：规格、黑帧、冻结、静音比例、响度、切点落拍比例。硬切检测有两种：画面整体变化大的切换，加上「相邻帧差突然变大」的切换（同一个房间、同一层界面叠加下的机位切换也能抓到）。
- **构图三项**（专门抓「做成网页 / 幻灯片」）：
  - 画面空不空：一半以上面积是同一种底色的帧占多少。≥50% 就是大片留白、空底摆卡片 → 放大主体、铺满场景。
  - 构图变化：相隔 3 秒以上的画面有多像。>0.45 就是版式重复、机位不变 → 换景别、换角度、换构图。
  - 每秒变化：相邻两秒的画面有多像。>0.82 就是像幻灯片翻页 → 加相机运动、加镜头切换。
  这三项报警告必须改到通过再交付。只有两种风格可以用开关放过：纯色大底快切的动态排版加 `--allow-solid-bg`；固定界面的交互网页录屏、说明书加 `--fixed-layout`。其他风格不许用开关消警告。
- **动态十项**（专门抓「静帧好看、动起来软、飘、一直晃、每个动作一个样、同一个动作在重播」，`scripts/motion.py` 逐帧算光流，先扣掉镜头整体的推拉摇移再量）。门槛按 Opus 5.5 原片实测定的，原片（科学讲解、AI 素材包装、魔塔 MV、四渡赤水、「眩晕」剪辑动效）全部能过：
  - 动作快不快：完整动作最快时的速度（中位数）。< 每秒 350 像素（1920 宽）→ 动作太慢太小：缩短到 0.25–0.5 秒、加大位移。原片 370–963，GPT-6 默认 219–453。
  - 快动作够不够：每一帧里最快的那 10% 的速度（中位数）。< 每秒 170 像素 → 画面里没有真正快的东西：加飞入、冲刺、砸下。原片 178–515，GPT-6 默认 124–142。
  - 快起慢停：一下冲出去再软着陆的动作占比。< 15% → 物体动作改用 `travel`、`pop`、弹簧 f 2.5–4。原片 17–39%（地图纪录片的推进本来就平稳一些），GPT-6 默认 5–21%。
  - 慢起慢停：两头对称慢进慢出的动作占比。> 60% → 软、飘：`inOutCubic` 只给镜头用。原片 24–55%，GPT-6 默认 62–80%——这一项最能拉开差距。
  - 动作用时：一个动作从起动到停下（中位数）。> 0.8 秒 → 拖：缩短到 0.25–0.5 秒。
  - 原地晃动：漂浮、上下浮动这类原地小晃占画面的面积。> 15% → 一直在晃：把晃动幅度压到画面高 1% 以内，换成从 A 到 B 的动作。
  - 镜头在动：镜头推拉摇移的时间占比。> 90% → 镜头一直在动：推完停住，让动作在静止的镜头里发生。
  - 动作有长有短：完整动作的时长分散程度（四分位距 ÷ 中位数）。< 0.6 → 每个动作一个样：按动作类型混用 `drop`（0.12 秒）、`beat`（0.3 秒）、`pop`（0.2 秒）、大东西 `travel`（0.5–0.7 秒）。原片 0.73–1.41，只用一个走位函数的 GPT-6 0.20–0.45。
  - 起步有加速：一帧之内冲到全速的动作占比。> 35% → 起步太猛：入场改 `beat()`（先预备一下），砸下改 `drop()`（先慢后快）。原片 8%–32%。
  - 画面在重播：扣掉镜头运动之后，同一个镜头里隔固定时间（0.3–1.6 秒）画面又回到原样的时间占比（画面分 8×5 格分别看，一窗里 15% 以上的格子回到原样就算）。> 2% → 主动作写成了 `t % 周期` 的循环，每拍同一刀、同一下顿推：按拍点写成只发生一次的事件（见 `06-运动与镜头.md` 2b 节）。八条原片（含两条 Blender、一条产品宣传片）全是 0%；魔塔 GPT-6 第 6.2 版 4.6%（高潮镜头一道刀光每 0.77 秒重播一遍，MV 四条下限照样全过）。
  这十项报警告必须改到通过再交付，没有开关可以放过。
  - **MV、卡点、打斗这类一直热闹的片子加 `--style mv`**，再查八条（按魔塔 MV、「眩晕」两条原片定，两条都能过）：动作最快 ≥ 每秒 650 像素（原片 952、973）；一个动作 ≤ 0.5 秒（原片 0.30、0.47）；镜头在动 ≥ 35%（原片 74%、39%）；没有明显动作 ≤ 15%（原片 11%、3%）；在动的面积 ≥ 16%（原片 22%、18%）；最长一次停顿 ≤ 0.5 秒（原片 0.2 秒）；辅层偏薄的镜头 ≤ 20%（每帧平均不到 2 层辅动作，原片 8%、17%）；成段全空的镜头 ≤ 10%（一成以上的帧什么都没动，原片 0%、0%）。只按通用几项做，GPT-6 会往保守走：魔塔 6.1 镜头只动 14%、空档 38%；6.3 事件写对了，动作却拖到 0.5 秒、最快只有 596、对峙停了 0.53 秒；6.4 动作快了（999），伴奏层却没了，在动面积掉到 15%；6.5 打斗重击加了碎片和拟声字，安静镜头照样空（29% 的镜头辅层偏薄、36% 有成段全空）。
- 看 `qa/逐帧条_开头.jpg`、`qa/逐帧条_最热闹.jpg`（每格间隔 0.2 秒，2.4 秒 12 格）：数一数同一时间在做「从 A 到 B」动作的东西有几样。少于 3 样就返工——主动作之外加跟随动作和一串依次飞入、拼装的小物件。
- 看 `qa/联系表.jpg`（每 2 秒一帧）：整体节奏、风格是否一致、有没有死画面。
- 看 `qa/手机尺寸.jpg`（每秒一帧，每张 360 宽）：手机上字还看得清吗？
- 快动作附近，抽 12 帧连续看：`ffmpeg -ss <t-0.2> -i 成片.mp4 -vf "scale=320:-1,tile=12x1" -frames:v 1 qa/strip.jpg`。
- 有声音的片子，至少听 / 测一遍：高潮点是不是落在最重要的画面上；旁白和字幕是否同步。

## 2b. 自检循环（返工单）

```
python3 <skill>/scripts/selfcheck.py 成片.mp4 --out qa              # 没有参考片：按硬门槛
python3 <skill>/scripts/selfcheck.py 成片.mp4 --out qa --ref 原片.mp4  # 有参考片：不比参考片差太多
```

- 它把全片按硬切分成镜头，逐个镜头查：动作慢（最快每秒不到 350 像素）、动作拖（一个动作超过 0.8 秒）、慢进慢出（超过六成）、一直在晃（原地小晃占画面 15% 以上）、镜头从头推到尾、几乎没东西在动、画面在重播（这个镜头每隔多少秒回到原样）。
- 返工单末尾列出项目代码里所有「时间 % 周期」的行（`--src` 指定目录，默认成片所在目录），逐行核对：主角动作、刀光、镜头顿推用了就改成事件，背景小效果可以留。这一项只列清单、不算不合格（Opus 原片代码里也有十来处，都是背景小效果）。
- 还读成片旁边的 `docs/分镜.md`（或 `--board 路径`）：「动作 / 事件 / 相机」这类栏有三成以上的镜头是同一句话，报「分镜动作复制」——每个镜头套同一套动作，做出来就是每个镜头同一个循环（魔塔 6.2 版：31 个镜头 25 个同一句）。
- 写出 `qa/返工单.md`：时间段、问题、量到的数、改哪个参数（比如「dur 改成 0.3–0.5」「ease 从 inOutCubic 换成 E.outQuart」「镜头关键帧改成先停 → 快推 → 停住」）。
- 照单改，只删掉这些时间段的帧重渲，合成后带 `--round 2` 再跑；**循环到返工单清空，最多 3 轮**。第 3 轮还没清空，把剩下的写进交付说明。
- 每轮的返工单都留着，交付说明的「自检」一节写：跑了几轮、每轮剩几个问题、最后还差什么。
- **改一项、看全部，防跷跷板**：每轮返工后，把动态十项（MV 再加八条）和上一轮逐项比。哪一项比上一轮差一成以上，先查是不是这次改动挤掉了别的层——为了快把碎片火花删了、为了不循环把飘尘也删了、为了画面满把主动作拖慢了——挤掉了就补回去再交。魔塔 MV 6.3–6.6 四轮实测：每轮新教的那一项都做到了，别的项就松一截（6.3 画面满、动作慢；6.4 快了、画面空；6.5 镜头追上、安静镜头空；6.6 安静镜头满了、高潮弱了）。

## 3. 打分和返工

按 SKILL.md 第四节的 10 项打分，写进 `qa/评分.md`：

```
硬要求 9｜风格辨识度 7｜开头 8｜可读性 6｜运动质量 8｜节奏 8｜声画同步 9｜内容核心 8｜构图 8｜技术 9
最差 3 个问题：
1. 12.4–14.0 秒 字幕两句叠在一起（可读性）
2. 第 3 段纸纹太淡，缩小后看不出撕纸风（风格）
3. 20 秒猫的颜色和前面不一致（风格 / 一致性）
修法：…
```

修完只重渲受影响的秒数（删掉那段帧再跑 render.mjs），重新合成，再跑一遍 qa.py 和打分。**全部 ≥ 8 才交付**；时间到了还没到 8，把差在哪写进交付说明，别假装没问题。

## 4. 专门要找的毛病

- 字：出画、被挡、两句叠在一起、停得太短、缩小后看不清。
- 画面：黑帧、闪帧、某个元素提前冒出来、穿模、图层顺序错、渲染没加载完的空白。
- 运动：匀速直线、全体同步、死画面超过 1.5 秒、镜头之间只有淡入淡出；动作拖到 1 秒以上、两头对称慢进慢出、一直原地晃、镜头从头推到尾、同屏只有一样东西在动。
- 风格：某几段丢了质感层；角色前后不一致；颜色跑出色板。
- 声音：高潮没对上；卡点片切点不在拍上；不要配乐的片子垫了底噪；旁白和字幕不同步；音频比视频短，或结尾突然断掉。
- 内容：反转、要点没演出来；数字或事实没查证；画面上出现了自证角标或水印。

## 5. 交付说明要写的（`交付说明.md`）

1. 一句话：这条片子是什么，多长，什么规格。
2. 导演单硬要求逐条：做到了没有（做到 / 部分 / 没做到，没做到写原因）。
3. 做法：路线、主要工具和库。
4. 素材和声音来源：每个外部素材的来源和授权；配乐是给的、曲库的还是合成的；旁白用的什么声音。
5. 自检：qa.py 的结果、最后一次评分、还剩的问题。
